# Исправления UI - 2026-09-24

## ✅ Исправленные проблемы

### 1. network_type с заглавной буквы
**Проблема**: API Stack Console возвращал ошибку 422 "The selected network type is invalid"

**Причина**: Мы отправляли `network_type: "isolated"` (с маленькой буквы), а API ожидает `"Isolated"` (с заглавной)

**Решение**: Изменили значения в `VMCreateWizard.tsx`:
- `networkType: 'Isolated'` (вместо `'isolated'`)
- `networkType: 'VPC'` (вместо `'vpc'`)

**Файлы**:
- `src/components/VMCreateWizard.tsx` - строки 700-780

---

### 2. Чекбокс Public IP не отображался
**Проблема**: Визуально не было видно что чекбокс выбран

**Причина**: Chakra UI компоненты `Box` не всегда корректно рендерят динамические стили

**Решение**: Заменили Chakra UI `Box` на обычный `div` с inline стилями и event handlers:
```tsx
<div 
  style={{
    border: `2px solid ${formData.publicIp ? '#0ea5e9' : '#e5e7eb'}`,
    backgroundColor: formData.publicIp ? '#f0f9ff' : 'white',
  }}
  onClick={() => setFormData({ ...formData, publicIp: !formData.publicIp })}
>
```

**Файлы**:
- `src/components/VMCreateWizard.tsx` - строки 820-870

---

### 3. Не отображался Storage Volume и Public IP в VMDetailPage
**Проблема**: В деталях ВМ не показывался размер storage volume и публичный IP

**Причина**: 
- Поля `storage_volume` и `public_ip` отсутствовали в типе `VirtualMachine`
- Нормализация не извлекала эти поля из API ответа
- VMDetailPage не отображала эти поля

**Решение**:

#### 3.1 Добавлены поля в тип VirtualMachine
```typescript
export interface VirtualMachine {
  // ... существующие поля
  storage_volume?: number;
  public_ip?: string | null;
}
```

**Файлы**:
- `src/api/types.ts` - строки 3-17

#### 3.2 Обновлена нормализация в client.ts
```typescript
// Извлекаем публичный IP отдельно
let public_ip: string | null = null;
if (apiVM.ipaddresses && Array.isArray(apiVM.ipaddresses)) {
  const publicIP = apiVM.ipaddresses.find((ip: any) => ip.is_public || ip.ip_type === 'public');
  if (publicIP) {
    public_ip = publicIP.ip_address || publicIP.ip || null;
  }
}

// Извлекаем storage volume
const storage_volume = parseInt(
  offering.storage || apiVM.storage_volume || apiVM.blockstorage?.size || '0', 
  10
) || disk;
```

**Файлы**:
- `src/api/client.ts` - строки 30-60

#### 3.3 Добавлены карточки в VMDetailPage
Добавлены три новые карточки:
1. **Приватный IP** - показывает `vm.ip_address`
2. **Публичный IP** - показывает `vm.public_ip`
3. **Storage Volume** - показывает `vm.storage_volume` в GB

**Файлы**:
- `src/pages/VMDetailPage.tsx` - строки 163-220

## 🧪 Проверка

### 1. Создание ВМ
1. Откройте сайт
2. Нажмите "Создать ВМ"
3. Перейдите на шаг "Network"
4. Выберите "Isolated" или "VPC" - должно работать
5. Нажмите на чекбокс "Публичный IP адрес" - должен стать ярким с галочкой
6. Завершите создание ВМ

### 2. Детали ВМ
1. Откройте список ВМ
2. Нажмите на любую ВМ
3. Должны увидеть 8 карточек:
   - CPU
   - Память
   - Диск
   - Приватный IP
   - Публичный IP
   - Storage Volume
   - Зона
   - Создана

### 3. Консоль браузера (F12)
При загрузке деталей ВМ должны быть логи:
```
Normalizing VM: vm-xxx
Offering data: { cpu: '4', memory: '4096', storage: '50' }
Extracted config: { cpu: 4, ram: 4, disk: 50, memoryMB: 4096 }
Normalized VM: { ..., storage_volume: 50, public_ip: '89.145.168.10', ... }
```
